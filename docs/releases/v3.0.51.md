## 🚀 Chi Tiết Bản Phát Hành (GitHub Release Description)

### 🌟 Điểm Nổi Bật (Highlights)

Phiên bản **v3.0.51** là bản vá khẩn cấp tập trung vào tính ổn định của tính năng **Phóng To AI (Upscale Studio)**. Một race condition tiềm ẩn trong pipeline xử lý file của NCNN-Vulkan đã được phát hiện và khắc phục triệt để, chấm dứt tình trạng một số ảnh sau khi upscale bị xuất ra với nội dung hoàn toàn màu đen.

---

### 1. Sửa Lỗi Phóng To AI — Ảnh Upscale Bị Màu Đen

#### Hiện Tượng
Sau khi chạy upscale (realcugan / realesrgan / waifu2x), một số ảnh trong batch — thường là ảnh có kích thước lớn hoặc xử lý liền kề nhau — bị xuất ra dưới dạng file hợp lệ nhưng **toàn bộ nội dung là màu đen**. Lỗi xảy ra ngẫu nhiên, không nhất quán và phụ thuộc vào kích thước ảnh cùng tốc độ I/O của hệ thống.

#### Root Cause — Race Condition 2 Lớp trong `NcnnBatchRunner`

**Lớp 1 — Stability check quá nhanh (40ms × 1 chu kỳ):**

`checkCompletedFiles()` chạy polling mỗi 40ms và sử dụng logic "file size ổn định trong 1 chu kỳ" để quyết định đọc file. Tuy nhiên, OS write buffer có thể giữ nguyên kích thước file trung gian trong suốt 2 lần poll liên tiếp (80ms) trong khi NCNN vẫn đang flush dữ liệu ra đĩa → file được copy khi chưa hoàn chỉnh → ảnh đen.

**Lớp 2 — Stderr `done` event bypass stability guard:**

NCNN `-j 1:1:1` pipeline sử dụng 3 thread độc lập: **preload → process → save**. Sự kiện `done` được emit bởi **process thread** trước khi **save thread** hoàn tất ghi file. Code cũ gọi `processCompletedEntry()` ngay lập tức khi nhận sự kiện này, bỏ qua hoàn toàn stability check.

#### Fix Đã Áp Dụng

| Thay đổi | Mô tả |
|----------|-------|
| `prevFileSizes` nâng cấp lên `{ size, count }` | Yêu cầu `count >= 2` (3 polls × 40ms = **≥120ms** ổn định) thay vì 1 poll (40ms) trước khi xử lý file |
| Stderr `done` event không còn bypass stability | `handleChunk()` chỉ add vào `readyEntries` rồi gọi `checkCompletedFiles()`; stability guard luôn được áp dụng |
| `childClosed=true` là fast-path duy nhất | Khi process NCNN đã kết thúc (exit code 0), mọi file còn lại được xử lý ngay — an toàn vì NCNN đã flush toàn bộ trước khi thoát |

#### Tác Động Hiệu Năng
Độ trễ thêm tối đa **≤120ms/ảnh** — không đáng kể so với thời gian upscale thực tế (thường 2–60 giây/trang tùy model và GPU).

### 2. Bộ Kiểm Thử Hồi Quy (Regression Tests)

Bổ sung **7 test case mới** vào `NcnnBatchRunner.test.js` để bảo vệ fix này khỏi bị vô tình revert trong tương lai:

| Test | Mục đích |
|------|---------|
| `does NOT trigger after only 1 same-size poll` | Xác nhận behaviour cũ gây lỗi đã bị loại bỏ |
| `does NOT trigger after 2 same-size polls` | count=1 chưa đạt ngưỡng STABLE_POLLS=2 |
| `triggers only after 3 consecutive same-size polls` | Ngưỡng ≥120ms hoạt động đúng |
| `resets stability counter when file size changes` | Phát hiện đúng file đang được ghi thêm |
| `each file tracked independently` | File nhỏ không bị block bởi file lớn đang ghi |
| `stderr done event: adds to readyEntries only` | Không gọi processCompletedEntry ngay lập tức |
| `tile-percentage lines return empty events` | Không có trigger nhầm từ dòng progress % |
